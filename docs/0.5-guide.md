# Renewal Engine 0.5 candidate guide

0.5.0 is a local release candidate. The public release is still 0.1.0 until a
concrete 0.5 publication is approved and verified. This guide describes the
current source and package, not a claim of external or human validation.

Requires CPython 3.11+. Inspection, review, comparison and summary export use only
the standard library and require no network account. All output destinations
must be new; their parent directories must exist. Run directories are private
(mode 0700). Keep raw source and evidence private unless you review them yourself.

## Choose and inspect recipes

```sh
python3 -m renewal_engine recipes
python3 -m renewal_engine conformance
mkdir -p .runs
python3 -m renewal_engine inspect ./your-project --out .runs/inspection \
  --recipe configparser-local-prefix-v1 --recipe pathlib-local-hardlink-v1
python3 -m renewal_engine verify .runs/inspection
```

Order is explicit. Unknown, empty or duplicate selections are refused. Default
inspection keeps the ConfigParser recipe. Composition runs each recipe against
the previous candidate and records every input/output/contract digest. The two
shipped recipes have disjoint supported bindings; both orders are tested.

The Path recipe supports an undecorated top-level function beginning with a
local `from pathlib import Path`, two direct `Path(parameter_or_constant)`
assignments, then `source_path.link_to(destination_path)`. It converts that call
to `destination_path.hardlink_to(source_path)` while preserving surrounding
bytes and comments. Aliased imports and the `target=` argument are supported.
Unknown bindings, dynamic mutations, subclasses, conditional flow and complex
argument expressions remain unchanged for review.

Open `report.html`, `changes.patch` and `impact.json`. Impact traces local imports,
relative imports/reexports and reverse dependencies; lists exported signatures;
and reads root pyproject/requirements/lock/configuration metadata. Unresolved
imports and pin conflicts are review hints, not a resolver or complete call graph.
Source inspection never imports or executes the selected project. Only bounded
Python source is copied; metadata is separately retained and hashed.

## Select changes and bind an approval

```sh
python3 -m renewal_engine hunks .runs/inspection
python3 -m renewal_engine approve .runs/inspection --source ./your-project \
  --hunk EXACT_HUNK_SHA256 --out .runs/selected
python3 -m renewal_engine verify-approval .runs/selected --source ./your-project \
  --sha256 EXACT_APPROVAL_SHA256
```

Copy the actual returned identities. Repeat `--hunk` to select multiple hunks.
The new `candidate/` contains selected changes; rejected hunks retain original
bytes. This local command approves an exact artifact, not behavioral equivalence
or an automatic edit of the original project. Any original change, including an
unrelated edit, invalidates the approval. Inspect the updated original into a
new directory, review its hunks and characterize the new candidate. The previous
inspection, rejected selection and approval remain available for audit. No
three-way merge, automatic conflict resolution or auto-apply is implemented.

## Compare repeated observations

Prepare two JSON arrays of 2–10 observation objects and a policy before comparing:

```json
{"schema_version":1,"owner":"maintainer","reason":"Exact contract","rules":[]}
```

```sh
python3 -m renewal_engine compare --original old-runs.json --candidate new-runs.json \
  --policy policy.json --out .runs/comparison
python3 -m renewal_engine verify .runs/comparison
python3 -m renewal_engine export-summary .runs/comparison --out .runs/share.json
```

`PASS` means supplied observations match under that frozen policy. Their origin
is not independently established by this command. `UNSTABLE` exposes unexplained
within-side variance even when a pair of runs matches across versions. `REGRESSION`
identifies unauthorized differences. Invalid types, duplicate JSON keys, nonfinite
numbers and malformed rules are refused. Exact JSON pointer rules may normalize
only equivalent timezone representations, bounded numeric differences or an
explicit unordered multiset. Raw observations remain unchanged; the result holds
the policy and its hash. See [the precise policy contract](observations.md).

The summary exporter verifies the saved evidence, then writes only allowlisted
status, counts and hashes. It excludes source/member names, paths, raw output,
exception strings, policy reasons, environment and arbitrary caller strings.
It does not redact or publish the raw run. Keep the raw directory for reopening;
removing a private run is an ordinary local filesystem operation. No automated
broad cleanup command is supplied.

## Measure the shipped migration

```sh
python3 -m renewal_engine hardlink-demo --baseline /absolute/python3.11.16 \
  --target /absolute/python3.12.14 --out .runs/hardlink
python3 -m renewal_engine hardlink-demo --baseline /absolute/python3.11.16 \
  --target /absolute/python3.12.14 --out .runs/wrong-direction --negative-control
```

These must be actual trusted Linux x86_64 CPython runtimes, not shims. The bundled
AGPL reference is hash pinned. Baseline characterization completes before candidate
generation. Five cases run twice per side and capture return values, stdout,
exceptions (including errno and both filenames), the exact expected warning
transition, file bytes, directories and independently observed hard-link pairs.
The deliberately wrong direction must return exit 1 / REGRESSION. `verify` reopens
both results without executing source. Preserve actual hard links when moving
a raw hardlink run: copying linked files independently destroys that evidence and
verification correctly refuses it. The original ConfigParser `demo` and 0.1 saved
normal/negative examples remain supported.

## Explicitly execute a Python snapshot

```sh
python3 -m renewal_engine isolation-probe
python3 -m renewal_engine execute ./your-project --entrypoint main.py \
  --authorize-execution --out .runs/execution
python3 -m renewal_engine verify .runs/execution
```

This narrow Linux x86_64 profile requires an existing non-setuid `/usr/bin/bwrap`,
working namespaces/seccomp and a trusted dedicated CPython prefix (the interpreter
running the CLI). A broad `/usr` or `/usr/local` interpreter prefix is refused.
Every execution runs fresh host-file/network/process denial probes and checks
runtime identity. There is no unsandboxed fallback.

Only the selected Python snapshot is available at `/project`, read-only. The
single writable file is `/work/output`, bounded to 64 KiB by default. No sockets,
child processes, threads, new files/directories, host home, inherited credentials
or `/proc` are available. CPU, memory, wall time and captured output are bounded.
This does not run package installers, test frameworks that spawn children, build
tools or general filesystem workflows. Read [the threat model and verified
limitations](isolation.md) before using it. Results distinguish infrastructure
failure, application nonzero exit and successful execution; none establishes
old/new equivalence. Raw captures, output-file hashes and copied source identities
are saved privately.

## Build and verify the candidate

```sh
python3 -m unittest discover -s tests -v
python3 tools/plan.py check
python3 tools/build.py
python3 dist/0.5.0/renewal-engine.pyz --version
```

Builds are deterministic and stored under `dist/0.5.0/`, preserving old 0.1 files.
The source archive contains the standard-library-only installer, CLI, tests,
recipe contracts, both references and documentation. Use an empty explicit prefix
with the archive's `install.py`; it refuses an existing installed command.
Public 0.5 download and fresh external evidence are separate release gates.
